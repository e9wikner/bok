# Phase 04 Plan 01: Rewrite the Canonical Deployment Guide

<objective>
Rewrite DEPLOYMENT.md into a LAN-first Swedish deployment checklist with a separate optional public-domain HTTPS path.
</objective>

## Objective

- **What:** Replace `DEPLOYMENT.md` with a LAN-first Swedish deployment guide for prerequisites through first login, plus a clearly separate optional public-domain HTTPS path.
- **Why:** Phase 4 needs one executable owner-facing deployment path instead of mixed on-premise, Hetzner, Terraform, backup, monitoring, and maintenance instructions.
- **Output:** `DEPLOYMENT.md` becomes the canonical guide for requirements `DEPL-01`, `DEPL-02`, `DEPL-03`, `DEPL-04`, `CONF-01`, `CONF-02`, `CONF-03`, `CONF-04`, and `DOCS-02`.

<threat_model>
Documentation mistakes in this plan can cause real operational damage. The key threats are:
- Owners deploy with placeholder secrets or Compose fallback credentials.
- Owners expose a LAN deployment publicly without HTTPS/domain prerequisites.
- Owners run destructive volume commands during first deployment.
- Owners follow outdated Terraform/Hetzner instructions as if they are validated.

Mitigations:
- Put required-secret replacement before startup.
- Keep public-domain HTTPS in a separate optional section.
- Include an explicit first-deployment warning not to use `docker compose down -v` for normal deployment.
- State that Terraform/Hetzner repair is outside the recommended path for this milestone.
</threat_model>
