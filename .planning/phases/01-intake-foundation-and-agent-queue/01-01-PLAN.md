<objective>
As a user, I want the backend to persist one uploaded voucher source file as a pending intake item before any voucher exists, so that source material can enter the accounting workflow without bypassing storage, duplicate, lifecycle, or path-safety constraints.
</objective>

<context>
This plan builds the durable intake foundation behind Phase 1. It deliberately stops at service/repository behavior and focused tests; API route exposure is Plan 01-02 and agent voucher linkage is Plan 01-03.
</context>

<threat_model>
**Assets:** uploaded PDF/image source files, persisted source metadata, SHA-256 duplicate keys, lifecycle status, actor/timestamp metadata.

**Threats:**
- HIGH: arbitrary file read if a persisted path can point outside `INTAKE_DIR`.
- HIGH: duplicate source uploads create duplicate pending work.
- MEDIUM: partial writes leave a file on disk without a DB record or a DB record pointing to a missing file.

**Required mitigations:**
- Implement and test a root-containment helper that rejects any resolved path outside `settings.intake_dir`.
- Enforce duplicate detection in both service logic and SQLite uniqueness on `intake_sources.sha256`.
- Persist metadata and status through repository/service methods only; do not put SQL in route handlers in later plans.
</threat_model>

<must_haves>
<truths>
- D-01: one uploaded PDF/image is one intake item with file metadata, hash, explanation, lifecycle status, and actor/timestamp metadata.
- D-02: Phase 1 does not model batches or multi-file intake items; users combine supporting files before upload.
- D-03: duplicate uploads are rejected with a clear conflict response; they are not silently treated as success.
- D-04: intake items include optional `source_type`.
- D-05: `source_type` supports `receipt`, `supplier_invoice`, `customer_invoice`, `reimbursement`, and `other`.
- D-06: uploaded intake items are not editable after upload.
- D-14: intake files are stored under a separate `INTAKE_DIR` root.
- D-15: every file access must enforce configured-root containment.
</truths>
</must_haves>
