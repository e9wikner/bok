<objective>
Build the `Intag` workspace where users upload voucher source files and bank CSV files, filter a unified intake table by lifecycle status/type, and navigate to posted vouchers or detail review surfaces.
</objective>

<context>
This plan consumes the API client/hooks from Plan 03-01. It should mirror the dense operational pattern from `frontend-v3/app/vouchers/page.tsx`, not a marketing or landing page.
</context>

<threat_model>
**Assets:** uploaded files, bank account selection, source status/error summaries, linked voucher navigation.

**Threats:**
- HIGH: bank upload submits an incorrect or empty `bank_connection_id` because the visible account selector is not tied to backend options.
- MEDIUM: failed uploads clear the selected file/explanation, forcing users to reconstruct input after a validation error.
- MEDIUM: status is communicated by color alone.
- MEDIUM: processed rows bury the posted voucher link behind a secondary action.

**Required mitigations:**
- Disable bank upload until a concrete `BankConnectionOption.id` is selected.
- Preserve failed form fields until the user changes them.
- Pair every status badge with Swedish status text.
- Make the posted voucher link the primary row action when `linked_voucher_ids[0]` exists.
</threat_model>
