<objective>
Provide the frontend with typed API methods, React Query hooks, and missing human review endpoints so the Phase 03 UI can upload intake material, list/filter all statuses, open item details, and render voucher-linked source/correction context.
</objective>

<context>
The upload endpoints exist, but the current backend read surface is not sufficient for the user-facing review loop. This plan adds read/composition endpoints only; it must not change posting semantics, storage paths, or immutable voucher correction behavior.
</context>

<threat_model>
**Assets:** uploaded source metadata, bank connection identifiers, linked voucher IDs, processing errors, correction history, file download URLs.

**Threats:**
- HIGH: a frontend endpoint exposes `stored_path` or another local filesystem path.
- HIGH: static review routes are shadowed by dynamic `/{id}` routes, causing file/detail requests to resolve incorrectly.
- MEDIUM: bank upload UI exposes only opaque connection IDs, leading users to select the wrong account.
- MEDIUM: voucher source context merges intake source material into manual attachments, weakening audit traceability.

**Required mitigations:**
- Return relative authenticated download URLs only, never `stored_path`.
- Declare `/workspace` and `/connections` routes before dynamic route parameters.
- Return bank connection display fields including `account_number`, `bank_name`, `iban`, `currency`, and `status`.
- Keep voucher source context as a separate response from existing manual attachment endpoints.
</threat_model>

<action>
Add static routes before `/{source_id}` in `api/routes/intake.py`: `GET /api/v1/intake/workspace` and `GET /api/v1/intake/workspace/{kind}/{item_id}`. `workspace` accepts `status`, `kind`, `limit`, and `offset`. It returns `items`, `total`, `limit`, `offset`, and `status_counts`. Ordinary items use `kind: "voucher_source"` and include source metadata, `download_url: "/api/v1/intake/{id}/file"`, latest processing summary/error, and `linked_voucher_ids`. Bank items use `kind: "bank_input"` and include bank input metadata, `download_url: "/api/v1/bank-inputs/{id}/file"`, imported/skipped counts, `detected_format`, `parse_error`, `transaction_ids`, `transaction_count`, compact `match_signals`, and `linked_voucher_ids`. The detail route returns full metadata plus `processing_attempts` for voucher sources and parse/import/transaction details for bank inputs. Add repository helpers `IntakeRepository.list_by_status`, `IntakeRepository.count_by_status`, `IntakeRepository.list_links_for_source`, `BankInputRepository.count_by_status`, and `BankInputRepository.list_voucher_links_for_input` as needed.
</action>
