## Screen Contracts

### Intake Workspace

| Contract | Decision |
|----------|----------|
| Route placement | Place the workspace under or directly beside `Verifikationer`; avoid a new top-level sidebar item. |
| Layout | Use the same operational page shell as `frontend-v3/app/vouchers/page.tsx`: constrained content, page header, filter card, data table card, pagination/status controls. |
| Primary focal point | The unified intake table is the visual anchor after upload panels; status badges and the row action draw the first scan. |
| Upload panels | Show two sibling upload panels above the table: `Verifikationsunderlag` and `Bankfil`. Do not merge their forms. |
| Type separation | Use a visible type badge or icon+label column in the unified table: `Underlag` and `Bankfil`. |
| Filters | Use compact filter chips for lifecycle status and type; no status tabs or kanban lanes. |
| Row action hierarchy | For processed rows with linked vouchers, primary action is the posted voucher link. Intake detail remains secondary. For failed or needs_attention rows, primary action is intake detail. |
| Mobile behavior | Upload panels stack vertically; filter chips wrap; table scrolls horizontally without shrinking text below 12px. |

### Intake Detail

| Contract | Decision |
|----------|----------|
| Purpose | Dedicated audit/detail surface for metadata, source files, processing attempts, warnings/errors, actor, timestamps, and linked vouchers. |
| Focal point | Status summary and latest processing attempt appear first; raw processing history follows as a chronological record. |
| Processed items | Show linked voucher number as the primary action: `Öppna verifikation`. |
| Failed or needs_attention items | Show the actionable error summary near the top, then raw attempt history. Do not introduce a guided remediation flow in this phase. |
| File access | File links use authenticated backend download URLs only; never expose filesystem paths. |

### Voucher Detail Extensions

| Contract | Decision |
|----------|----------|
| Source material | Add a dedicated `Källmaterial` section separate from manual attachments. Include both voucher sources and bank inputs, clearly typed. |
| Processing notes | Add an audit-style `Agentbearbetning` section with summaries, warnings/errors, actor, and timestamps. |
| Correction learning | Add a `Korrigeringskedja` section when correction history exists. Show original voucher, correction voucher(s), reason, and the sentence `Den här historiken kan användas av agenten vid framtida bokföring.` |
| Visual separation | Manual attachments stay in their existing attachment area. Intake source material must not be visually merged with manual uploads. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge icon gaps |
| sm | 8px | Compact button gaps, filter chip gaps, table row metadata gaps |
| md | 16px | Default form field spacing, card content padding on compact surfaces |
| lg | 24px | Page section spacing, card headers, upload panel internal spacing |
| xl | 32px | Major page blocks and desktop grid gaps |
| 2xl | 48px | Empty states and large loading groups |
| 3xl | 64px | Reserved for page-level breathing room only; avoid inside dense work surfaces |

Exceptions: icon-only buttons and touch targets use fixed 40px minimum to match existing `Button size="icon"`; mobile hit areas may expand to 44px minimum without changing the spacing scale.

## Typography

Use exactly these four sizes and two weights for Phase 03 UI work.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 or 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 18px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Display text is reserved for page titles only. Table cells, badges, form help, and audit metadata use Label or Body. Do not add responsive viewport-based font scaling in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` / light `#fcfcfc` | Page background and unframed layout surface |
| Secondary (30%) | `hsl(var(--card))`, `hsl(var(--secondary))`, `hsl(var(--muted))` / light `#ffffff`, `#f4f5f7` | Cards, filter bars, table headers, sidebar-adjacent surfaces |
| Accent (10%) | `hsl(var(--primary))` / light `#2662d9` | Primary upload CTA, active filter chip, active navigation/link to posted voucher, focus ring |
| Destructive | `hsl(var(--destructive))` / light `#ef4444` | Destructive actions only |

Accent reserved for: primary upload CTA, active filter chip, active navigation state, linked voucher primary row action, focus ring. Do not use accent for every link, every icon, or passive status decoration.

Semantic status colors:

| Status | Badge Variant | Usage |
|--------|---------------|-------|
| pending | `secondary` | Waiting for agent work |
| processing | `outline` with spinner or clock icon | Agent is currently processing |
| processed | `success` | Completed and linked when applicable |
| skipped | `outline` | Intentionally not posted |
| failed | `destructive` | Processing failed |
| needs_attention | `warning` | User should inspect detail |

## Copywriting Contract

Primary UI copy must be Swedish, operational, and specific.

| Element | Copy |
|---------|------|
| Page title | `Intag` |
| Page description | `Ladda upp underlag och följ agentens bokföringsarbete.` |
| Primary CTA | `Ladda upp underlag` |
| Secondary upload CTA | `Ladda upp bankfil` |
| Voucher source panel title | `Verifikationsunderlag` |
| Bank upload panel title | `Bankfil` |
| Source explanation label | `Kort förklaring` |
| Bank account selector label | `Bankkonto` |
| Empty state heading | `Inga underlag i intaget` |
| Empty state body | `Ladda upp ett kvitto, en faktura eller en bankfil för att ge agenten nytt material att bokföra.` |
| Upload success | `Underlaget har lagts till i intaget.` |
| Bank upload success | `Bankfilen har lagts till i intaget.` |
| Error state | `Uppladdningen misslyckades. Kontrollera filtyp, bankkonto och att filen inte redan finns i intaget.` |
| Failed row action | `Granska fel` |
| Needs attention row action | `Granska underlag` |
| Processed voucher action | `Öppna verifikation` |
| Intake detail secondary action | `Visa intagspost` |
| Destructive confirmation | No persisted destructive action is introduced in Phase 03. Clearing a local selected file uses `Rensa vald fil` without confirmation because nothing has been saved. |

Forbidden generic labels: `Submit`, `OK`, `Cancel`, `Save`, `Klicka här`, `Spara` without a noun.

## Component Inventory

| Need | Contract |
|------|----------|
| Buttons | Reuse `Button` variants `default`, `outline`, `secondary`, `ghost`, and `destructive`. Include lucide icons for upload, filter, voucher link, file, warning, and history actions. |
| Cards | Use `Card`, `CardHeader`, `CardTitle`, `CardDescription`, and `CardContent` for upload panels, filters, table containers, detail sections, and voucher extension sections. Do not nest cards inside cards. |
| Badges | Reuse `Badge`; add only the smallest required variant/class extension for intake statuses if existing variants cannot express `processing` or `needs_attention`. |
| Tables | Follow `frontend-v3/app/vouchers/page.tsx`: `text-sm`, muted header row, 16px cell padding on desktop, horizontal overflow on mobile. |
| Skeletons | Use `Skeleton` rows for table loading and block skeletons for detail loading. |
| Forms | Use existing input styling pattern: rounded border, `bg-background`, 14px text, `focus:ring-2 focus:ring-ring`. File inputs may be wrapped in a dashed drop area but must keep a visible file picker fallback. |
| Icons | Use lucide icons only: recommended `Upload`, `FileText`, `Landmark`, `AlertTriangle`, `CheckCircle2`, `Clock`, `History`, `ExternalLink`, `Download`, `Brain`. Icon-only controls require `aria-label` and `title`. |

## Accessibility and Interaction Rules

| Area | Contract |
|------|----------|
| Focus | Every upload field, chip, row action, and file link must show the existing `ring` focus treatment. |
| Status | Do not communicate lifecycle status by color alone; pair badges with Swedish text. |
| Errors | Table summaries may truncate visually, but detail pages must show full error text. |
| Upload feedback | Keep the user on the intake workspace after success, show compact success text, refresh counts/table, and do not clear failed form fields until the user changes them. |
| Keyboard | Filter chips and row actions must be keyboard reachable in visual order. |
| Source downloads | Download buttons must identify the file name in accessible text. |
