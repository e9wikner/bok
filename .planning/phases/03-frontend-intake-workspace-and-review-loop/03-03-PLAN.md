<objective>
Complete the review loop by adding dedicated intake detail pages and extending voucher detail with linked source material, agent processing notes, and correction history that remains visible for learning.
</objective>

<context>
This plan consumes the source-context and detail APIs from Plan 03-01. It should preserve the existing voucher correction workflow and manual attachment UI while adding separate review sections.
</context>

<threat_model>
**Assets:** source file download URLs, processing attempt history, correction reasons, linked voucher navigation.

**Threats:**
- HIGH: source files are linked using local storage paths instead of authenticated API download URLs.
- MEDIUM: correction history is presented as editable state rather than immutable review context.
- MEDIUM: intake source material is visually merged with manual attachments.
- MEDIUM: failed item detail hides full error text behind table truncation.

**Required mitigations:**
- Use only `download_url` or API URL helper output for source file links.
- Render correction chain as read-only history.
- Add `Kallmaterial` separate from existing `Bilagor`.
- Show full `error_detail`, warnings, summaries, actor, and timestamps on detail pages.
</threat_model>
