<objective>
Add the voucher detail UI for creating correction notes, reviewing suggested draft corrections, and approving or dismissing them.
</objective>

<requirements_addressed>
- CORR-01: User can leave a text correction note on a posted voucher.
- CORR-04: User can review and approve a suggested correction before posting.
- CORR-06: Correction note lifecycle is visible in the UI.
</requirements_addressed>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser input to correction note API | User free text is sent to the backend and later to an agent. |
| Editable draft rows to approval API | User edits accounting rows before posting the B-series draft. |
| Terminal note state to user display | Applied, dismissed, and rejected states must be visible without enabling unsafe actions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-08 | Tampering | Suggested correction rows | mitigate | Disable approval when local debit/credit totals are unbalanced; backend still validates before posting. |
| T-09-09 | Repudiation | Dismiss action | mitigate | Use explicit confirmation copy and backend terminal history; UI does not silently discard suggestions. |
| T-09-10 | Information Disclosure | Voucher detail cards | accept | Correction notes are shown only on authenticated voucher detail pages already exposing voucher data. |
</threat_model>
