<objective>
Expose correction notes to agents and preserve dismissed/rejected suggestion context for the agent learning loop.
</objective>

<requirements_addressed>
- CORR-02: Agent can read pending correction notes.
- CORR-03: Agent can suggest a B-series correction based on a correction note.
- CORR-06: Correction note lifecycle is tracked and visible to agents.
</requirements_addressed>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored user note to external agent | User-entered correction text is sent to an authenticated agent. |
| Agent queue to voucher APIs | Queue items provide action URLs for draft correction work. |
| Terminal history to learning loop | Dismissed/rejected data influences future agent behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Information Disclosure | Agent queue | mitigate | Expose note text and safe voucher/action URLs only; do not expose local filesystem paths or hidden intake workspace data. |
| T-09-06 | Tampering | Queue item lifecycle | mitigate | Queue lists only `pending` notes; suggestion/rejection state changes go through authenticated voucher-scoped routes. |
| T-09-07 | Repudiation | Agent learning context | mitigate | Terminal dismissed/rejected notes are recorded through correction history with actor, reason, and timestamp. |
</threat_model>
