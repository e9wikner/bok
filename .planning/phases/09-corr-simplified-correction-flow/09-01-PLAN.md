<objective>
Add backend storage, lifecycle service, and voucher-scoped APIs for correction notes and draft B-series correction suggestions.
</objective>

<requirements_addressed>
- CORR-01: User can leave a text correction note on a posted voucher.
- CORR-03: Agent can suggest a B-series correction based on a correction note.
- CORR-04: User can approve a suggested correction before posting.
- CORR-05: Approved correction produces an immutable B-series voucher.
- CORR-06: Correction note lifecycle is tracked.
</requirements_addressed>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User free text to accounting workflow | Correction note text influences agent-generated accounting suggestions. |
| Agent suggestion to draft voucher | Agent-supplied rows become a draft B-series voucher, but not a posted voucher until user approval. |
| Draft voucher to posted immutable record | Approval posts a correction voucher and must not mutate the original voucher. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | Original posted voucher | mitigate | Approval posts only the draft B-series voucher; original posted voucher remains unchanged and linked through `correction_of`. |
| T-09-02 | Repudiation | Dismissed/rejected suggestions | mitigate | Dismiss/reject paths write terminal note status and correction history with suggested rows or rejection reason. |
| T-09-03 | Elevation of Privilege | Note/draft endpoints | mitigate | Keep all routes protected by `get_current_actor`; do not expose unauthenticated mutation paths. |
| T-09-04 | Integrity | Duplicate active notes | mitigate | Add a partial unique index for statuses `pending` and `suggested`; service returns `409` on active-note conflicts. |
</threat_model>
