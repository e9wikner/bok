## 1. System Classification

**System Type:** Documentation-only / HTTP-agent onboarding verification

**Description:**
Phase 7 documents how an owner connects an external OpenClaw-style HTTP agent to
a deployed Bok instance. Bok does not run a model, orchestrate prompts, perform
RAG, or implement an agent framework in this phase. Good output is accurate
deployment documentation and verified copy-paste commands for existing HTTP
endpoints.

**Critical Failure Modes:**
1. Documentation tells the owner to use the human frontend URL instead of the
   backend API URL for OpenClaw.
2. Documentation exposes or repeats secrets unnecessarily in examples.
3. Verification commands drift from actual route paths or bearer auth behavior.
4. Documentation implies unsupported AI features such as MCP, persistent
   per-agent keys, generated tool schemas, or durable idempotency.

## 1b. Domain Context

> Researched by `gsd-framework-selector`; no AI-domain researcher was needed
> because the phase does not build an AI system.

**Industry Vertical:** Swedish small-company bookkeeping deployment

**User Population:** Owner-operator deploying Bok on a LAN server and connecting
an external HTTP-capable agent.

**Stakes Level:** High

**Output Consequence:** Incorrect setup instructions can prevent agent
connectivity, leak credentials, or encourage the agent to use unsupported startup
paths.

### What Domain Experts Evaluate Against

| Dimension | Good | Bad | Stakes | Source |
|-----------|------|-----|--------|--------|
| URL separation | Human frontend and agent backend URLs are unambiguous. | OpenClaw is pointed at port 3000 or Docker-internal `http://api:8000`. | Agent cannot connect or connects through the wrong surface. | `07-CONTEXT.md` D-05 to D-09 |
| Auth correctness | Bearer auth uses `Authorization: Bearer <BOKFOERING_API_KEY>` and verification calls the ping endpoint. | Docs present placeholder key lifecycle endpoints or omit auth verification. | Agent setup fails or owner trusts an unverified connection. | `07-CONTEXT.md` D-04, D-14, D-15 |
| Scope honesty | Docs describe only current HTTP onboarding behavior and deferred unsupported features remain out of scope. | Docs imply MCP, generated tool schemas, persistent keys, or model orchestration exists. | Owner or agent follows non-existent paths. | Phase 6 context and Phase 7 roadmap |

### Known Failure Modes in This Domain

- LAN users copy `BACKEND_URL=http://api:8000` from `.env.production`, but that
  hostname only works inside Docker Compose.
- Users confuse the frontend URL on port 3000 with the backend API URL on port
  8000.
- Curl examples that inline secrets are copied into logs or support reports.
- Long starter prompts drift from the public entrypoint and become stale.

### Regulatory / Compliance Context

Bok remains a bookkeeping system with immutable posted vouchers and correction
voucher semantics. Phase 7 must not weaken those guardrails in documentation.
The external agent is allowed to make bookkeeping decisions, but Bok's backend
continues to enforce formal constraints.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|----------------|
| Bok maintainer | Verify documented paths against FastAPI routes and auth behavior. |
| Owner-operator reviewer | Confirm setup checklist can be followed after first login without reverse engineering. |

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|------------|-----------------|
| Agent entrypoint | Public-safe HTTP startup contract at `/api/v1/agent-instructions/entrypoint`. | OpenClaw setup starts here. |
| Bearer credential | `BOKFOERING_API_KEY` sent as `Authorization: Bearer ...`. | Protected agent endpoints, especially ping. |

### Common Pitfalls

1. Do not use `http://api:8000` outside Docker Compose.
2. Do not give OpenClaw the frontend URL on port 3000 as the API base URL.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|---------------------------|----------------------|----------|
| Route accuracy | Pass if every documented route exists or is intentionally public/protected as described. | Code/source assertions + pytest/httpx | Critical |
| Auth accuracy | Pass if documented ping command uses bearer auth and unauthenticated ping fails. | pytest/httpx | Critical |
| URL clarity | Pass if docs distinguish port 3000 frontend, port 8000 backend, optional HTTPS API domain, and Docker-internal `http://api:8000`. | Documentation source assertions | High |
| Scope honesty | Pass if docs do not claim MCP, persistent keys, generated tool schemas, or durable idempotency are supported. | Documentation source assertions | High |

### Eval Tooling

**Primary Tool:** pytest

**Setup:**
```bash
.venv/bin/pytest tests/test_agent_entrypoint.py
```


backend URL, frontend URL, public HTTPS note, and Docker-internal URL warning.

Bok maintainer review is sufficient; no LLM judge or human AI-output rubric is
