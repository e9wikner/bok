<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner docs to external agent | Documentation tells an external HTTP agent which URL and credential to use. |
| Local secrets to shell examples | `BOKFOERING_API_KEY` is copied from `.env.production` into local shell variables for verification. |
| LAN/public URL guidance | Documentation translates Docker Compose internals into reachable owner/agent URLs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | `DEPLOYMENT.md` command examples | mitigate | Use `API_KEY` shell variable and `Authorization: Bearer ${API_KEY}`; do not repeat inline secret values or include expected response snippets. |
| T-07-02 | Spoofing | OpenClaw setup URL guidance | mitigate | Document the reachable backend API URL `http://SERVER_IP_OR_HOSTNAME:8000` and separate it from the frontend URL and Docker-internal `BACKEND_URL=http://api:8000`. |
| T-07-03 | Tampering | Starter OpenClaw instruction | mitigate | Delegate startup behavior to `/api/v1/agent-instructions/entrypoint` and make the first prompt setup-only so docs do not duplicate stale workflow steps. |
| T-07-04 | Repudiation | Unsupported key lifecycle/MCP/idempotency claims | mitigate | Do not document persistent agent keys, MCP, generated tool schemas, durable idempotency, or key lifecycle routes as supported Phase 7 behavior. |
</threat_model>
