<objective>
Add backend storage and API support for per-source agent guidance.

This plan creates the canonical `agent_guidance` field, accepts it during
voucher-source upload, supports locked updates before processing completes, and
exposes a uniform `guidance` field to agents.
</objective>

<requirements_addressed>
- GUIDE-01: User can attach an agent message to an uploaded receipt/invoice.
- GUIDE-02: Agent message is visible to the agent when processing the intake item.
- GUIDE-03: Agent message is displayed on the intake detail page through API data returned to the frontend.
</requirements_addressed>

<must_haves>
<truths>
D-01: Use `agent_guidance` for DB column, request/response field, domain field, repository argument, service argument, and frontend API type.
D-02: Add `PUT /api/v1/intake/{id}/agent-guidance`.
D-08: Allow updates only for `pending` and `processing`.
D-09: Return `409 Conflict` for non-editable statuses.
D-10: Store missing or whitespace-only guidance as null.
D-11: Do not add guidance storage to bank inputs.
D-12: Agent queue includes `guidance` for every item; bank inputs use null.
</truths>
</must_haves>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input to stored source metadata | Guidance is free text stored with intake source material. |
| Stored guidance to external agent | Guidance is sent to an authenticated external accounting agent. |
| Source state to edit API | Source status determines whether user text can still change. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `PUT /api/v1/intake/{id}/agent-guidance` | mitigate | Service must reload source and allow updates only for `pending` and `processing`; all other statuses raise `IntakeConflictError`. |
| T-08-02 | Information Disclosure | Agent queue | mitigate | Return only guidance text and existing safe metadata; never expose `stored_path` or deleted metadata through queue items. |
| T-08-03 | Repudiation | Guidance edit lifecycle | accept | Phase does not require guidance edit audit history; source status lock and voucher traceability remain enforced. |
| T-08-04 | Spoofing | Update actor | mitigate | Keep route protected by `get_current_actor`; do not make guidance update public. |
</threat_model>
