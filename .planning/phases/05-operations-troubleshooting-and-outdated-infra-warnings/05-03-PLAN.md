# Phase 05 Plan 03: Expand Troubleshooting and Mark Outdated Infrastructure

<objective>
Expand owner-facing troubleshooting in DEPLOYMENT.md and clearly mark Terraform/Hetzner documentation as outdated and excluded from the recommended deployment path.
</objective>

## Objective

- **What:** Add operational troubleshooting coverage and update infrastructure warnings.
- **Why:** Owners need enough diagnostic commands to report or diagnose deployment problems without following stale infrastructure instructions.
- **Output:** `DEPLOYMENT.md`, `README.md`, and `terraform/README.md` satisfy `OPS-04` and `DOCS-04`.

<threat_model>
Troubleshooting docs can leak secrets or steer owners into stale infrastructure paths. The main threats are:
- Owners paste full `.env.production` into support channels.
- Owners follow Terraform/Hetzner docs as if they are validated.
- Owners cannot distinguish LAN connectivity failures from public DNS/HTTPS failures.

Mitigations:
- Provide support-ready diagnostics that avoid secret values.
- Add a top-of-file Terraform/Hetzner warning.
- Separate LAN troubleshooting from optional public-domain DNS/HTTPS checks.
</threat_model>
