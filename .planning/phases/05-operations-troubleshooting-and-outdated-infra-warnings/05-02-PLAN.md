# Phase 05 Plan 02: Document Backup and Restore Operations

<objective>
Extend DEPLOYMENT.md with practical backup and restore instructions for the SQLite/data volume and local backup directory.
</objective>

## Objective

- **What:** Add Swedish owner-facing backup and restore instructions for LAN and optional public-domain deployments.
- **Why:** Updates and rollback are only safe if owners know how to preserve and restore bookkeeping data.
- **Output:** `DEPLOYMENT.md` satisfies `OPS-02`; `.env.production.example` stays aligned if backup comments need clarification.

<threat_model>
Backup/restore documentation can damage the accounting record if it is vague or implies unvalidated off-site backup behavior. The main threats are:
- Owners back up only the Git checkout and miss the persistent data volume.
- Owners restore over current data without understanding that current bookkeeping data is replaced.
- Owners assume optional S3 settings are validated backup infrastructure.

Mitigations:
- Identify `bokfoering-data` and `/app/data` as the protected data.
- Use explicit local backup directory and verification commands.
- Mark optional S3 settings as placeholders/future configuration unless validated separately.
</threat_model>
