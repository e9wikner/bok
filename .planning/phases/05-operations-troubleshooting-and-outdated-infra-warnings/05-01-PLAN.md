# Phase 05 Plan 01: Document Safe Updates and Rollback

<objective>
Extend DEPLOYMENT.md with a safe LAN-first update flow and concrete rollback instructions that protect bookkeeping data.
</objective>

## Objective

- **What:** Add owner-facing Swedish sections for normal updates and rollback after a failed update.
- **Why:** Owners need a repeatable update path that starts with backup and avoids destructive Docker volume commands.
- **Output:** `DEPLOYMENT.md` satisfies `OPS-01` and `OPS-03` for the recommended LAN deployment path.

<threat_model>
Operational documentation mistakes can cause data loss. The primary threats are:
- An owner runs `docker compose down -v` during an update and deletes the persistent SQLite/data volume.
- An owner updates without a backup and cannot recover after a bad deployment.
- An owner checks out a previous commit for rollback but does not rebuild or verify the running services.

Mitigations:
- Put backup confirmation as the first update step.
- Repeat warnings against `down -v`, deleting Docker volumes, and removing `bokfoering-data`.
- Include concrete update, rollback, and verification commands.
</threat_model>
